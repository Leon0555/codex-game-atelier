# ADR 0005：状态、结果与证据契约

- 状态：Accepted（v1 基础契约；多文件提交协议仍需独立薄切片验证）
- 日期：2026-08-24；更新：2026-08-25
- 决策范围：CLI 结构化结果、任务/交接状态和 evidence 引用

## 背景

Codex 负责判断与编排，CLI 负责确定性执行。若两者共享非结构化日志或把任务状态、命令退出码和验收结论混在一起，恢复、CI 和独立审计都会依赖脆弱的文本解析。

## 决策

1. 使用 JSON Schema Draft 2020-12，初始 schema 版本为 `1.0.0`。
2. 分离命令结果、稳定错误、evidence、任务、handoff 和 project state。
3. CLI 结果与任务生命周期使用不同状态集合；`NOT_RUN` 永不等于 `PASS`。
4. CLI 使用稳定的退出码类别；底层 Godot 退出状态作为数据/evidence 保留。
5. command/task/handoff 中的 evidence reference 必须指向 `.gameatelier/` 内的 evidence record；record 自身的 `path` 可以指向项目内的日志、报告或构建/导出产物，因此使用受约束的通用项目相对路径。两者不能混为同一语义。
6. 状态只保存恢复所需事实，不保存隐藏思维链、后台规划器状态或具体模型 ID。
7. 破坏性 schema 变化需要新 ADR、迁移预览、备份和回退。
8. 项目内状态与 evidence 根目录使用 `.gameatelier/`，生产者标识使用 `gameatelier-cli`。该命名在首个生产实现前确定；更早的状态根命名只存在于未发布草案和 fixture 中，没有已发布状态需要迁移。
9. 时间戳采用可互操作的 RFC 3339 canonical 子集：大写 `T`/`Z`、小数秒只用 `.`、秒为 `00..59`、时区小时为 `00..23` 且分钟为 `00..59`；不接受闰秒或 Go 解析器的额外宽松形式。
10. `detect`、`doctor`、`status` 保持零文件写入；`initialize` 只建立项目状态，不写 evidence。`validate`、`test`、`build`、`export` 等门禁/引擎执行命令默认在 `.gameatelier/` 持久化结构化 run 与 evidence，不能依赖用户额外运行 `validate` 才留下必要证据。`release check` 的后续只读聚合例外由 ADR 0016 修订本条。
11. `manual`、`standard`、`strict` 决定门禁深度与必须满足的检查集合，不决定关键操作是否留 evidence；三种模式的门禁/引擎执行命令都记录最小可审计事实。模式不能作为关闭安全检查、结果记录或失败证据的开关。
12. evidence 持久化不得产生 `.gameatelier/` 之外的隐藏状态或网络写入。构建/导出产物只能写到命令明确声明且通过 containment 检查的项目相对目标；遥测仍默认关闭。

## 备选方案

### 只输出自然语言或控制台日志

拒绝。CI、恢复和审计会被迫解析不稳定文本。

### 一个巨型 run/state 文件

拒绝。命令、任务与产物生命周期不同，单文件放大锁冲突、隐私面和迁移风险。

### 直接采用引擎内部对象模型

拒绝。v1.0 的公共边界只保留 Godot 实际验证的通用语义，不把场景树或资源类型变成状态系统。

## 风险

- 初始字段可能在 Rust/Go 与 Godot 薄切片中暴露不足。
- JSON Schema 不验证文件存在、hash 正确或日志已脱敏，需要运行时和测试补足。
- 稳定错误码过早细分会形成维护负担，因此 v1 先冻结类别，具体代码按实际失败逐步加入。

## 迁移与回退

基础 schema、命令类别与默认持久化政策已经接受。多文件提交顺序、正式引用点、崩溃恢复和 state revision 更新仍必须通过独立 ADR/薄切片冻结；不得从单文件 `initialize` 推导其原子性。后续破坏性变化通过新 schema 版本迁移，不原地静默改写旧状态。更早的未发布状态根草案不作为兼容输入，因为它从未形成发布契约；若将来发现真实外部使用，再通过显式迁移决策处理。
