# Security Policy

## Supported versions

| Version | Supported |
| --- | --- |
| Latest `1.0.x` release | Yes |
| Preview builds, release candidates, branches, and local candidates | No |

Only the latest published patch in the `1.0.x` line receives security fixes. A superseded patch stops receiving fixes when its replacement is published.

## Reporting a vulnerability

Do not include exploit details, credentials, personal data, or other sensitive material in a public GitHub issue or discussion.

GitHub Private Vulnerability Reporting is enabled and verified for this repository. Use it for sensitive vulnerability reports. Use public issues only for non-sensitive security hardening or documentation problems; do not publish a sensitive vulnerability report publicly.

The project does not request passwords, tokens, Apple signing credentials, Godot account access, or unpublished game assets as part of a vulnerability report.

## Scope

Security reports may cover the Codex Plugin, bundled Go CLI/private runner, Starter Template, file-backed state and evidence handling, explicit optional Git-hook helper, packaging/upgrade/rollback behavior, or release verification. Godot itself, Codex clients, GitHub, and operating-system security controls are upstream products; reports that demonstrate an Atelier integration defect are still in scope.
